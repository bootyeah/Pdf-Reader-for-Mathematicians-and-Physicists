## 9 项修复结果

| 原问题 | 现在的行为 |
| --- | --- |
| 1. 不支持的思考参数 | 当前 Kimi、GLM、Gemini 型号使用统一能力表。Kimi K3 使用 `reasoning_effort`；不可关闭的型号禁用聊天开关，管理器仅列受支持档位。旧的不兼容设置保留并明确提示，请求前报错。 |
| 2. Kimi 多轮历史丢失 | 正文和 `reasoning_content` 保留原文，贯通流式聚合、保存、刷新、后端清洗和下一轮请求。按实际请求模型标记来源，切换或回退到其他模型时不混发 Kimi 推理字段。另修复连续刷新时初始化写回空历史的问题。 |
| 3. 提示词预览不符 | 管理器按图片、电脑手写、手机手写和白板场景解析当前草稿。手写预览和实际识别共用构造函数，空的第二模型提示词继承当前识别用途；白板固定段落提示词只读显示。 |
| 4. OCR 回退过窄 | 通用 429 与暂时性 5xx 可尝试备用模型一次；已识别的额度、鉴权和参数错误不重试。 |
| 5. null 被当成识别结果 | 统一验证正文和结束原因，null、非文本、拒答、工具调用及预算截断明确报错；保留原有空字符串“未检测到内容”的处理。 |
| 6. 截断误判完成 | 检查结束原因和结束标记，断流、截断、无正文会提示；部分内容仍可查看和复制，但不进入已完成历史。纯 usage 帧正常传递。 |
| 7. 切页改写档位 | 渲染无副作用；前后端共用能力表。不兼容旧值保留原值，等待用户显式选择；不再把 max 等档位悄悄映射成 high。 |
| 8. 测试预算误判 | 根据具体型号的默认思考能力选用测试预算，思考测试最多 4096 tokens，仍遵守用户设置的更小上限。区分连接成功但输出未完成，并显示实际预算。 |
| 9. 联网格式不通用 | 只允许已核实的 GLM 官方托管搜索端点，发送完整的 `web_search.enable` 结构。其他端点禁用新开启操作，旧的开启值允许关闭；运行时明确报错，翻译不再悄悄退回离线。 |

补充官方依据：[OpenAI 模型相关推理档位](https://developers.openai.com/api/docs/guides/reasoning)、[GPT-5.4](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.4)、[GPT-6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)、[GLM 托管联网搜索](https://docs.bigmodel.cn/cn/guide/tools/web-search)、[Z.ai 托管联网搜索](https://docs.z.ai/guides/tools/web-search)。未收录的自定义网关型号保留原有兼容路径，并标明档位由接口决定；没有迁移到 Responses API 或新增客户端工具执行循环。
