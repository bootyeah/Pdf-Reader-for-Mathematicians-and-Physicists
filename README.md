## LaTeX 实时预览与宏包管理

编辑思维导图节点或批注文字（包括高亮附注、文本块）时，编辑区旁自动显示实时预览。优先放在右侧，空间不足时移到左侧或上下方；预览随拖动、缩放和滚动定位，结束编辑后关闭。预览复用文本块的红色光标：文字处显示闪烁竖线，公式处显示半透明红色虚线框，随输入、方向键和占位符跳转同步，并滚动到光标位置。沿用原有速录、保存、取消和撤销行为。普通公式延迟 30ms 更新，TikZ 延迟 300ms，复用现有编译缓存。

双击根目录 `LaTeX-Manager.bat` 打开独立宏包管理工具，可增删 TikZ 宏包及导言命令、TikZ / PGFPlots 库、绘图环境。保存写入 `static/config.js` 的 `LATEX_CONFIG`，刷新阅读器后生效；保留其它配置和快捷键，并可恢复上一版 LaTeX 配置。备份与工具会话保存在 `.latex-manager/`，无需打开阅读器即可使用。管理工具不含公式宏设置，速录仍由快捷键管理工具负责。

普通公式使用 `static/lib/katex/` 中的本地浏览器渲染器，已加载 mhchem 这一 KaTeX JavaScript 扩展；KaTeX 不能加载任意 TeX `.sty` 宏包。TikZ 才调用本机 TeX Live 的 `xelatex` 与 `dvisvgm`，`LATEX_CONFIG` 中的宏包与库用于图形自动生成的导言区。管理工具不安装 TeX 宏包，也不替换用户完整文档中的导言区。

## 2026-10-12 PDF 批注缓存串文档修复

PDF.js 使用内置 `/ID`，无 ID 时使用前 1KB 指纹；两种标识都可能被不同 PDF 共用。已核实 Stein 的 Fourier Analysis 与 Complex Analysis 两份文件具有相同的 `/ID`，导致无内嵌批注的前者读到后者的缓存。现在在首屏绘制后，由批注 worker 对页面树、正文流、字体和图像资源生成 SHA-256 内容指纹（取前 128 位），确认身份后才恢复本地批注。指纹不依赖原 `/ID`、对象编号、文件名和 Info 批注字段，因此保存批注及改名不改变关联。Worker 不可用和局域网 HTTP 环境也使用相同算法，切换文件后迟到的身份结果会被丢弃。

旧的 ID/前缀指纹缓存仍保留在浏览器中，但无法可靠判断其归属，因此不会再自动读取；PDF 中已经保存的批注照常读取。旧云端备份和 JSON 导入的指纹也可能不匹配，需在确认所属文档后手动导入。若旧批注已写进 PDF，此修复不会自动删除文件内的批注。刷新阅读器并重新打开 PDF 后生效。

回归：`node tests/reader-document-identity.cjs`（相同内置 ID、同名同大小同前 1KB 的不同 PDF 隔离、保存及改名后的稳定性、旧缓存保留、兼容路径及迟到恢复）、`node tests/reader-data-integrity.cjs`、`node tests/reader-cloud-races.cjs`。两份实际教材另以只读文件和内存保存验证，分别正确读取 0 / 122 条内嵌批注，不修改原始 PDF。

## 独立 API 管理工具

双击根目录 **`API-Manager.bat`**，会在浏览器中打开独立的本地管理页面，无需先启动阅读器。重复双击会打开同一个管理服务；点「退出管理工具」结束服务，不会关闭阅读器。仅关闭标签页会保留服务。需要 Python 3.10 或更新版本，启动器优先使用系统 Python，当前电脑也可使用已有的 Codex Python 环境；管理工具本身没有额外包依赖。

左侧有六项功能：**内置对话、单词 / 短语词典、整句 / 段落翻译、图片公式识别、手写 / 手机识别、公式识别第二模型**。每项均可独立配置：

- API 地址、API Key、主要模型、备用模型；地址可填 Base URL（保留 `/v1` 等前缀）或完整 `/chat/completions` 地址。
- Key 可独立保存，也可共用另一项功能的 Key。共用只影响 Key，接口和模型仍独立；不允许循环引用。
- 温度、超时、输出 token 上限、思考模式、直连 / 系统代理 / 指定代理、提示词。对话可添加模型菜单的额外选项；词典提示词应保留 JSON 输出结构。
- 「读取接口模型列表」请求当前地址的 `/models`；不支持此接口的服务仍可手填模型 ID。
- 「测试当前连接」测试**未保存的草稿**，显示耗时、HTTP 状态与响应。使用固定短句或内置公式图片，不读取 PDF，不自动尝试备用模型，最多生成 256 tokens，可能产生少量费用。开启思考后若没有返回正文，可关闭思考重测。连接测试不保证词典格式或识别质量，最终还需用对应功能验证效果。

首次打开会从 `server.py`、`tex/config.json`、`airtex/config.json` 导入当前值，保存到 **`.api-manager/settings.json`**，以后以该文件为准，无需再改源码。原配置保留作为首次导入来源。原来的独立 `tex/run.bat`、`airtex/run.bat` 仍使用各自配置文件，本工具管理的是它们在阅读器中的调用。云端批注库的 GitHub / Gitee 凭证仍由 `cloud_config.json` 管理。

「保存全部设置」一次保存六项草稿，保留上一版 `.api-manager/settings.previous.json`；「恢复上一次保存」可回退参数与 Key。两个窗口同时编辑时，过期草稿会被拒绝覆盖。配置文件意外损坏时，有有效备份即可在管理页面恢复。

**安装本次更新后，重启阅读器 Python 服务并刷新阅读器页面一次。** 此后管理工具里的修改会在阅读器下一次调用时自动读取，已开始的请求不变。对话模型菜单在打开和发送前同步；配对中的手机在下一次识别时同步。

支持 **OpenAI 兼容的 Chat Completions 接口**，使用 Bearer Key。更换服务时，可把思考模式设为「不发送」，避免服务不认识 `thinking` 参数。原生 Anthropic / Gemini 等不同协议需要兼容网关，不能直接填写原生地址。图片输入要求所选模型具备视觉能力。

管理页只监听 `127.0.0.1`，使用随机端口和本地会话令牌，配置不上传到其他管理服务。已保存的 Key 默认明文显示并可复制；共用 Key 随来源草稿实时更新。独立 Key 输入留空或点击「清空」后，保存即删除。配置与备份包含明文 Key，请妥善保管，不要上传或分享。阅读器静态服务拒绝读取这些文件、Python 源码和旧密钥配置；`/api/read-file` 仅允许读取 PDF。

开发回归：`python tests/test_api_manager.py`、`node tests/reader-api-manager.cjs`，使用临时配置和本地模拟接口，不消耗真实模型额度。也可运行 `python api_manager.py`；`--no-browser` 只启动服务。`PDF_READER_API_CONFIG` 可指定配置文件路径，阅读器和管理工具应使用同一环境变量值。

## 文本编辑框中的公式输入（airtex + tex）

仍用 `start.bat` 启动阅读器。添加文本块并打开编辑框后，在输入区上方选择「手写 / 识图 / 手机」，无需另外启动两个工具，也没有新增阅读器工具栏按钮。

- **手写**：在框内用鼠标或触控笔书写，支持橡皮、撤销一笔和清空，再点「识别手写」。画板内 `Ctrl+Z` 撤销笔画。
- **识图**：点击「框选 PDF 公式」直接截取当前 PDF 的公式，或粘贴、拖入、选择图片；`Esc` 取消框选。图片就绪后点击「识别图片」。
- **手机**：配对卡片可选择「同一 Wi-Fi」或「互联网」，再扫描二维码。「互联网」支持手机使用移动数据或其他 Wi-Fi，详见下方说明。连接后二维码自动收起，原位置显示笔迹；按实际书写区域自动放大，点「整张画板」可看全貌。点「二维码」可再次查看配对卡片，不会重建连接。手机或电脑均可发起识别。同一 Wi-Fi 方式首次使用时需允许 Python 通过 Windows 防火墙访问专用网络。**收起手机面板、切到手写/识图、点击编辑框外部、重新打开编辑框或切换 PDF，都保留连接与手机笔迹，无需重复扫码。** 只有主动「重新配对」、退出/刷新阅读器页面或重启服务后才需要重新连接。两端均停止联系服务超过 30 分钟的闲置会话会回收。
- **插入**：识别结果默认只显示公式预览，需要修改时点「改代码」展开 LaTeX，然后点「插入光标处」。选中的文字会被替换；在已有 `$...$` 等数学环境内插入会去掉重复定界符。随后沿用编辑框原有的保存、取消、点击外部保存和批注撤销/重做。
- **第二模型**：三个模式按钮右边的独立按钮，初始对应原来的 DeepSeek 识别配置。默认不按时使用管理工具中的「图片公式识别」或「手写 / 手机识别」（初始为 GLM）；按下后，三种识别方式均使用「公式识别 · 第二模型」（初始与内置对话共用 Key）。再次按下切回默认模型。选择记在浏览器本地，手机配对期间切换也会在下一次识别时生效。

公式输入默认展开为 400×480 的紧凑窗口（小屏幕会限制在视口内，已手动放大的编辑框保留其尺寸）。拖动窗口后收起公式输入，只恢复展开前的宽高，保留最后拖动的位置。识别结果和「插入光标处」固定留在输入面板下方；代码按需展开，避免一直占据正文编辑空间。

手机端全屏书写时，右上角的橡皮和清空小按钮可直接操作笔迹，无需退出全屏；橡皮启用时按钮高亮，再点一次返回书写，清空沿用原有确认提示。公式识别与独立白板共用这套入口。手机端不显示识别结果代码，原有复制操作及电脑端结果显示保持不变。

手机画笔支持黑、红、蓝、绿、橙、紫六种颜色，点色块即可选择；选颜色时自动从橡皮切回画笔，刷新页面保留所选颜色。每笔独立保存颜色，电脑预览、翻页、本地恢复和识别图片保留彩色笔迹，旧笔迹仍按默认黑色显示。全屏时颜色板竖排在屏幕右侧，较矮屏幕可上下滑动颜色板。

全屏时点击右上角的连接指示灯，可折叠全部工具（包括颜色板、「显示工具」和右下角翻页按钮），只留下连接灯；再点连接灯恢复工具。连接灯仍随连接状态变色，折叠不改变笔迹、颜色、橡皮或防误触设置，也不退出全屏。

手机页面顶部新增「防误触」开关，全屏时为盾牌图标，开启后高亮并在当前网页记住选择，初次使用默认关闭。开启后过滤明显的大接触点，一笔书写或擦除期间只跟踪最先接受的触点，后来碰到屏幕的大面积手掌不会打断书写。两个正常大小的触点用于缩放、移动画布；浏览器能明确辨识笔尖时优先保留笔尖书写。普通电容笔仍可书写，但无法可靠区分单根手指和笔尖，效果取决于手机浏览器提供的接触面积；若笔尖被拦截可关闭开关。此设置同时适用于公式识别和手写草稿白板。

识别配置统一由上述 API 管理工具管理；尚未打开管理工具时兼容原有配置。识别需要联网，只有点击识别才会上传对应笔迹或所选图片。Python 需安装 Pillow（与原工具相同）；缺失时界面会提示安装命令。阅读器浏览器端拿不到密钥。原来的两个独立工具仍可单独运行。

修改后请重启已经运行的 Python 服务并刷新阅读器页面。自动回归：`node tests/reader-formula.cjs` 和 `python tests/test_formula_backend.py`，两者均使用模拟视觉接口，不消耗真实模型额度。

## 跨网络手机连接（互联网隧道）

白板和编辑框的手机配对卡片均有「同一 Wi-Fi / 互联网」选项。用 iPad 远程控制电脑时，在电脑阅读器中选择「互联网」，等待生成 HTTPS 二维码，然后用手机扫描 iPad 远程画面里的二维码即可；手机只需浏览器，无需额外 App、同一网络、路由器端口映射、Cloudflare 账号或域名。电脑需保持开机，阅读器服务与手机均需联网。

选择互联网方式后，后台为当前手写会话创建独立的 [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。准备期间隐藏旧二维码，显示建立连接或下载进度；失败后可点「重试连接」。切换方式或重试会保留电脑上的当前笔迹及识别结果，失败的远程连接不自动切到局域网。两个面板分别记住连接方式，后续打开自动沿用。暂时断网由隧道和手机原有同步机制自动重连；进程退出后需重试并扫描新二维码。

工具固定使用官方 cloudflared `2026.10.0`，Windows 64 位可执行文件在 `.phone-tunnel/cloudflared.exe`，首次缺失时后台从官方 GitHub 发布页下载并校验 SHA-256。下载失败可检查电脑网络后重试。可用 `PDF_READER_CLOUDFLARED` 指定已安装工具的完整路径；非 Windows 环境使用 PATH 中的 cloudflared。工具进程在 Windows 中隐藏运行，单独配置，不修改已有 Cloudflare 设置，不安装系统服务。

隧道只转发当前手机手写服务，保留随机配对令牌；不转发 `8080` 阅读器主服务、PDF 文件或 API 管理器。令牌随二维码包含在地址中，手写页设置 `no-referrer`，避免把配对链接作为来源发送到外部。获得完整配对链接的人可访问这张画板，请仅用于自己的手机。白板和公式输入的笔迹会经 Cloudflare 转发；识别仍由电脑调用已配置模型，API Key 留在电脑。

切回「同一 Wi-Fi」、重新配对、刷新/退出阅读器页面、闲置会话回收以及正常退出阅读器服务都会关闭对应隧道。收起或隐藏面板保留连接。Quick Tunnel 是临时服务，不保证可用性，重建隧道会更换地址；无法连接时可重试或使用同一 Wi-Fi。

**更新后请重启阅读器 Python 服务，并刷新电脑和手机页面。** 验证脚本：`python tests/test_phone_tunnel.py`、`python tests/test_formula_backend.py`、`node tests/phone-session.cjs`、`node tests/reader-formula.cjs`。显式运行 `python tests/phone-tunnel-live.py --live` 可用模拟画板验证真实外网 HTTPS、令牌校验、笔迹同步、模拟识别回传和关闭清理，不读取用户 PDF、不调用真实识别模型。

## 独立手写草稿白板

工具栏的**文本块按钮点第一次选择添加文本块，再点一次打开「手写草稿」白板，再点一次隐藏白板**。白板打开后可继续使用其他批注工具；点击窗口外部不会关闭。拖动标题栏移动，拖动任意边缘或四角自由调整宽高。标题栏右上角折叠按钮左侧新增**「纯白板模式」**按钮，点击后整块窗口沉浸展示为纯手写白板，标题栏与下方所有工具按钮全部藏起；白板右上角保留轻量退出按钮，再次点击或按 `Esc` 键即可退出纯白板模式。标题栏右上角「折叠」折叠为小条，再按「展开」恢复。「×」隐藏窗口，重新通过文本块按钮打开时，连接、笔迹和结果都保留。窗口位置、尺寸与模型选择会记住；笔迹与识别结果在本次阅读器页面内保留。

电脑白板显示时，按 V 键折叠/展开；输入框正常 V 打字和 Ctrl+V 粘贴保持原样。长按不会反复切换，隐藏或尚未打开白板时不触发。纯白板模式与折叠独立：折叠时显示可展开的标题栏，展开后仍恢复纯白板模式；手机连接和草稿不变。白板左下角不再显示笔迹数量。

白板扫码方式与编辑框相同，使用自己的二维码、笔迹会话、识别结果及模型选择。手机可写文字、公式和想法；电脑可切换自动放大笔迹/整张画板，并可清空。默认模型初始为 GLM，共用 API 管理工具中的「手写 / 手机识别」接口、Key 和模型参数；按下「第二模型」后共用「公式识别 · 第二模型」配置，初始为 DeepSeek。白板没有单独的管理项；其段落提示词固定在 `formula_bridge.py` 的 `WHITEBOARD_PROMPT`，不受这两个管理项中「提示词」输入框的修改影响。管理器的功能说明和提示词说明均标明了此区别。

点「识别为 LaTeX 段落」（或手机上的「识别段落」）后，使用白板独立提示词：**“输出这段内容在latex文档中相应段落的代码”**，保留文字、段落及推导顺序，行内公式用 `$...$`，独立公式用 `$$...$$`。正文不会整体套入数学环境，也支持纯文字草稿。下方可预览、改代码、复制或保存 `.tex`。点结果区「回到白板」或顶部「收起结果」，可收起整个预览和代码区，让画板恢复全部空间；已识别或手动修改的代码保留，点「查看结果」可再次打开，后台同步不会自动把旧结果弹回。新识别完成后会展示新结果。编辑框中的公式识别提示词和插入流程不受影响。只有点击识别才向模型发送内容。

手机手写草稿白板新增上一页、下一页和页码：在末页点下一页会新建空白页，也可回看和继续编辑之前的页。各页笔迹和撤销记录只存于手机浏览器本地，刷新同一配对网页可恢复；电脑端和识别接口只收到当前页。翻页会清除上一页的识别展示，正在进行的旧页识别结果不会落到新页；电脑清空也只清当前页。全屏时可翻页；点击连接灯折叠工具时，右下角翻页按钮也一并隐藏，再点连接灯恢复。编辑框中的单页手机公式输入保持原样。

手机同步改为收到服务端确认后才标记成功；短暂断网会保留本地笔迹并自动补传，后台返回时也会继续同步。修复旧版超过 4000 笔或单笔 4000 个点后静默截断的问题，并提高长草稿的传输容量。达到新的单页容量时会明确提示，保留原有笔迹，不再假报同步成功。手机页面与电脑页面均需刷新一次以加载更新。

手机公式输入和草稿白板均支持**无限画布**：单指书写，两指捏合缩放、同向拖动平移，可以继续在初始画板之外书写。横竖屏切换、全屏和结果面板变化只调整视野，保留笔迹坐标与粗细。左下角「查看全部」可让全部笔迹回到视野内。**「框选」**默认使用**自由套索**：沿任意轨迹画虚线圈，松手时自动闭合，选中圈内及与边界相交的整笔笔迹，再在圈内拖动整组内容；凹形与交叉轨迹按实际区域选择。也可在画布左上角切换为「矩形」，选择方式会记住。再点「框选」或选择颜色即可回到书写。全屏时框选按钮在左上角，选择方式在按钮下方；点击连接灯折叠工具时一并隐藏。移动和擦除均可撤销，白板每页分别保存笔迹、撤销记录和视角，刷新或翻页可恢复。电脑的贴合笔迹、整张画板预览和识别支持负坐标、远处笔迹；旧版有限画板数据仍兼容。**更新后重启阅读器服务，并刷新电脑和手机页面。**

## 核心架构与技术实现细节

1. 🎯 虚拟占位节点与高频坐标追踪 (Virtual DOM Placeholder & rAF Polling)
   - 解决原生 contenteditable 在复杂缩放下的光标定位难题。在文本输入态，动态向 DOM 注入零宽占位节点 (Phantom Node)。
   - 挂载基于 requestAnimationFrame (60fps) 的轮询引擎，实时读取占位节点 ClientRect，动态更新绝对定位的模拟光标。在页面滚动、缩放时，实现 0 延迟的物理级视觉同步。

2. 🚀 页高索引与 HUD 偏移映射 (Viewport Radar & HUD Offset Mapping)
   - 采用被动监听与 rAF 节流。页码定位、缩放位置和返回跳转共用 Fenwick 页高索引，查询为 O(log N)，避免反复线性累加长文档的全部页高。
   - 右上角悬浮 HUD 搭载逻辑偏移算法 (Logical Offset)，一键将任意物理页设为“正文第 1 页”，底层不改变任何核心渲染坐标，彻底分离视觉 UI 与物理状态。

3. 🧠 目录预解析与多级深度穿透 (Async Outline Parsing & Deep Penetration)
   - 摒弃传统的深层 DOM 遍历，在目录生成初期，将所有的目标映射 (Destination) 置于后台静默解析为物理页码，并降维压平为一个有序数组 (Flattened Map)。
   - 目录解析结果每帧批量排序，同页条目按目录本身的顺序排列。滚动时以 O(log M) 二分查询定位目录项，同页子目录优先，且不受父子目标解析完成顺序影响。

4. 🌌 虚拟页面窗口与跨页状态接力 (Virtual Page Window & Cross-Page State Machine)
   - 读取基准尺寸初始化页高索引，只挂载视口附近和当前交互需要的页面 DOM。近期离屏页面保留有界位图缓存；异形页真实渲染后按点修正索引。
   - 跨页拖拽引擎：当批注被拖拽跨越物理页边界时，底层状态机实时解除旧页绑定，重新计算相对于新页面的百分比坐标，并无缝重构撤销栈上下文。

5. 🧬 增量差异记录栈与指纹安全校验 (Delta History Stack & Fingerprint Auth)
   - 历史撤销栈 (Undo/Redo) 废弃全量深拷贝，采用 Delta 算法仅记录变化前后的 JSON 碎片，内存占用极低，支持长线历史回退。
   - 导出与持久化强制绑定 PDF 哈希指纹 (Fingerprint)。导入数据时自动拦截异构文档，提供“合并”与“覆盖”双层智能防污染策略。

6. 🛸 虚拟列表与无界时空侧翼 (Virtual List & Spatial Sidecar)
   - 侧边栏批注采用 Intersection Observer + 分块插入 (Chunk Size: 30) 实现原生虚拟列表，确保海量批注节点按需生成不卡顿。
   - 动态扩展草稿纸：阅读器右侧潜伏等宽隐形 DOM。当鼠标拖拽或绘制矢量线条逼近页面右侧 98% 物理阈值时，自动静默展开辅助草稿纸区域。

7. ⌨️ 原生快捷宏引擎与自适应防抖策略 (Vanilla Snippet Engine & Adaptive Debounce)
   - 零第三方依赖实现 LaTeX 快捷键展开 (如 mk 展开为 $$)。内置 Delta 增量追踪算法，支持 Tab 键在多个参数占位符 ($0, $1) 间精准跳转。
   - 针对渲染耗时差异，实施双轨防抖：前端纯文本/KaTeX 触发 30ms 极速重绘；包含 TikZ 的内容触发 300ms 延迟，避免高频请求阻塞后端。

8. 📐 CAD 级矢量交互引擎与正片叠底透视 (Vector Engine & Multiply Blend)
   - 独创“两段式活体宽度拉伸 (Live Thickness Expansion)”：允许用户先拉出方向基准线，松开鼠标后进入宽度微调阶段，实现 CAD 级别的自由高亮块绘制。
   - 所有图章与标注元素均采用纯数学二次/三次贝塞尔曲线构建原生 SVG。针对高亮标注采用原生 CSS `mix-blend-mode: multiply`，实现物理级的纸墨渗透效果。

9. 🎬 悬浮等比视频播放器与防干扰交互层 (Aspect-Locked Floating Video Player)
   - **B 站联网**：二维码、登录状态、分集信息、b23.tv 短链接和视频 CDN 请求固定直连，不继承 Windows 或环境变量中的 HTTP / HTTPS 代理，避免 Clash 退出后仍连接失效的本机代理端口。此规则只用于 B 站相关请求，不修改系统代理或 Clash 设置。
   - 边看教材边刷网课：按 `F9` 随时呼出/收起独立的悬浮深色磨砂晶体播放器，支持本地大文件视频秒开与 Range 进度条拖拽，本地视频离线播放。
   - **网址播放**：点击标题栏链接图标，输入 B 站视频网址或 MP4 / WebM / M4V / MOV / OGV 直链，再点「播放」。支持 BV / av 视频页、b23.tv 短链和官方播放器链接；自动读取分 P 或合集，沿用上一个 / 下一个按钮并保持网站顺序，带 `p=2` 等参数时从指定分 P 开始。B 站视频由本机服务按需转发到阅读器原有播放器，点击画面播放 / 暂停，不会跳转 B 站网页；原有倍速、外挂字幕、全屏和框选放大均可使用，关闭暂停并保留进度。
   - **B 站登录与高清**：网址输入栏下方点击「B 站登录」，用 B 站 App 扫码并确认；本机独立记住登录，无需提供密码。选择 1080P / 720P / 480P / 360P，按账号权限和源视频实际提供的清晰度播放，旁边显示实际结果。1080P 优先获取 DASH 音视频分离流，由本地附带的 dash.js 5.2.1 同步接入原有 `<video>`；不再只请求可能被限制在 720P 的合并 MP4。清晰度取自实际选中的视频流，而非播放接口的顶层标记。较低清晰度保留 MP4 播放。登录和切换清晰度保留进度、播放 / 暂停、倍速、外挂字幕和选区。扫码只在主动点击登录后开启，取消输入或关闭播放器即停止轮询。Windows 登录信息使用当前系统账号的 DPAPI 加密，保存在已受静态服务保护的 `.api-manager/bilibili-session.json`；点「退出」删除本机登录。媒体转发支持 Range 拖动和过期地址刷新，不预先下载整集，Cookie 不发送给前端或视频 CDN。二维码复用现有 Pillow 组件，无需增加 Python 依赖。更新后需重启 Python 服务并刷新页面，原登录继续保留。
   - **同文件夹切换**：通过打开视频按钮选择一个视频后，自动加载该文件夹直接包含的视频，按标题自然排序（如第 2 课在第 10 课之前）；标题栏的上一个/下一个按钮直接切换，列表两端停用对应按钮。双击画面或点击全屏图标进入视频全屏，仍可用标题栏切换视频并保持倍速。切换视频沿用原有行为，清除上一段视频的外挂字幕和裁剪；再次选择视频默认打开上次所在文件夹。需重启阅读器 Python 服务并刷新页面；无本地服务时，浏览器选择框支持多选视频形成列表。
   - **等比联动视口**：右下角自适应手柄严格按视频原始分辨率比例（如 16:9）联动缩放，杜绝传统自由拉伸导致的黑色多余背景与上下左右黑边。
   - **框选放大**：点击标题栏的裁剪图标，在画面上拖出与播放器同宽高比的选区，松手后放大播放。右上角原画小窗默认透明，鼠标悬停才显示，可拖动选区或点击新位置；再次点击顶部裁剪图标恢复完整画面，`Esc` 保留用于退出全屏。双击放大画面可全屏并继续调整选区；支持新版 Edge / Chrome，保留原生播放控制和外挂字幕。
   - **防误触与无干扰体验**：
     - 加入透明交互遮罩隔绝 Edge 浏览器“画中画/增强/翻译”浮动栏干扰；
     - 单击画面任意处即刻播放/暂停，双击切换全屏；
     - 快捷键调速主动失去媒体焦点，彻底杜绝浏览器原生蓝色/黑色选中边框；
     - 精简 4 档核心倍速（0.5x, 1.0x, 2.0x, 3.0x），配合 `Z`/`X` 键支持 0.1x 无级微调与外挂 `.srt`/`.vtt` 字幕热挂载。
     - 字幕加载后，点击字幕按钮可关闭/重新开启字幕，旁边的循环箭头按钮可更换字幕文件；关闭字幕后无需重新选择文件即可开启。
     - 视频窗口打开且不在输入状态时，单独按下并松开 `Shift` 即可折叠/展开窗口，折叠时保持播放；组合键、输入和鼠标拖拽不会触发。

10. 🏛️ 沉浸侧栏文档资产与界面降噪工程 (Sidebar Document Header & De-noised UI)
    - 顶部工具栏去除冗余标题与杂乱文字，将当前文档标题移至左侧边栏顶置沉浸展示，采用加粗中性灰排版，鼠标悬停支持一键快速复制完整文件名。
    - 全界面采用纯图标化极致轻量设计，无多余字样侵占视野，极大提升学术阅读与高密度批注专注度。

11. 🤫 一键静默收工与启动器隐身退出 (Silent Teardown & Invisible Launcher Exit)
    - 保存下拉菜单中的电源按钮即「一键收工」：后台先模拟 Ctrl+W 依次关掉本启动器打开的全部阅读器标签页，再终止 Python 引擎与终端，不必逐个页面反复点击。
    - 收到退出指令的第一时间即调用 `ShowWindow(SW_HIDE)` 把启动器黑框隐去，而不是等标签页关完、进程退出后才消失——因此页面上方不会再有终端停留几秒挡画面。
    - 实现细节：`GetConsoleWindow` 由 **kernel32** 导出（`user32` 里并不存在，误写会抛出 `function 'GetConsoleWindow' not found` 并被异常分支吞掉，表现为「隐藏从未生效」）；窗口句柄需显式声明 `c_void_p` 返回类型，否则 64 位 HWND 被截断。
    - 排障需要保留窗口时，可在启动前设置环境变量 `PDF_READER_SHOW_CONSOLE=1`；回归自检脚本：`python tests/test_hide_console.py`。

12. 📖 框选即译的词典工作流与短语解析 (Selection Dictionary & Phrase Insight)
    - 在 PDF 文本层框选词语即浮现「单词」「句子」气泡：单个单词给音标、词性、中英释义与例句；框到词组、固定搭配或习语时给出短语解析（意思 + 用法 + 例句）。**是词还是短语由模型判断**，前端与后端都不按空格猜——PDF 框选很容易把空白带进来（想把 `account` 框准却成了 `accou nt`），代码按空格切词就会把单词误判成短语；现在由模型先还原用户真正想查的词条再决定输出哪种结构，服务端从 JSON 的 `type` 字段读出 `kind` 回传前端选版式。
    - 翻译请求由 `server.py` 代理转发至管理工具所配置的模型，单词词典与整句翻译可分别配置。初始沿用原来的 DeepSeek 接口与关闭思考的设置。
    - **气泡尺寸与正文等比**：气泡的字号/内边距/图标全部由 CSS 变量 `--dict-scale` 驱动，JS 把 `state.scale` 写进去，于是气泡相对 PDF 文字的大小恒定（实测：页面 50% 时气泡 97×22、100% 时 191×42、230% 时 435×94，气泡高/文字高始终 ≈1.9）。基准值一律用 px 写死不依赖 rem，因此改根字号也不会走形。缩放时由 `#zoom-level` 的 MutationObserver + 容器滚动事件即时贴回选区。
    - 联网搜索开关 `ENABLE_WEB_SEARCH` 默认关闭：`{"type":"web_search"}` 并非官方内置工具，实测直接返回 400 `unknown variant web_search`，开着只会让每次查询白发一次注定失败的请求。

13. 🐋 DeepSeek 对话悬浮窗与流式 Markdown/LaTeX 渲染 (Whale Button & Streaming Chat)
    - 工具栏「搜索」左侧、红色 PDF 标志右侧独立挂一个鲸鱼气泡（本地内联 SVG，不联网、不依赖图标字体）。它刻意**不做进右边的视图控制条里**：不共用那个灰底胶囊，两者之间只留 `space-x-3.5` 的间距，因此视觉上不相连（实测鲸鱼按钮 424→458px，视图组自 472px 起，间距 14px）。
    - 点击后在其正下方展开可拖动、可缩放（右下角手柄）的对话框；位置/尺寸/模型/思考开关/对话历史全部记在 `localStorage`，刷新页面接着聊。`Esc` 收起，输入框内 `Enter` 发送、`Shift+Enter` 换行。
    - **流式输出**：前端 `fetch` 读取 SSE，服务端 `_chat_stream()` 把上游帧原样透传（`data: {"delta":...}` / `{"reasoning":...}` / `{"done":true}`），因此首字立即出现，不必等整段返回。渲染按 `requestAnimationFrame` 合帧，一帧最多重排一次——每个 token 都重排会让长回答明显卡顿。
    - **粘贴图片**：`Ctrl+V` / 拖拽 / 图片按钮三条入口都走同一套校验（PNG / JPEG / WebP / GIF，单张 ≤8MB，单条 ≤4 张）。⚠️ DeepSeek 视觉接口会**拒绝 1×1 这类退化像素图**，报 `unsupported image`——那是上游的尺寸校验，不是编码问题（实测 120×60 的正常 PNG 正常识别）。
    - **Markdown + LaTeX**：自带轻量渲染器覆盖标题/列表/表格/引用/代码块/强调，不引入任何第三方库；公式交给 `renderLatex` 的同一套 KaTeX `auto-render` 配置（与文本框批注完全一致，含 `\(...\)` 兼容定界符）。占位符机制保证公式里的 `*` `_` `[]` 不会被 Markdown 语法吃掉。
    - 模型下拉由管理工具中的主要模型和额外可选模型生成，初始保留 `deepseek-flash` 与 `deepseek-v4-pro`。思考默认值同样由管理工具设置，窗口里的「思考」按钮可临时切换；管理工具设置为「不发送」时按钮禁用。思维链显示在回答上方的可折叠区块里。
    - Key、模型、额外模型菜单、提示词与调用参数在独立 API 管理工具中修改，保存后自动读取；阅读器浏览器端拿不到密钥。接口为 `POST /api/chat`，服务端注入 system prompt、校验消息与图片，并把上游的 401/402/429/400 翻译成易懂的提示。
    - 空会话只显示鲸鱼图标与「DeepSeek 对话」字样（不放副标题与示例胶囊）；输入框 `placeholder=""`，不显示任何提示文字；头部扫帚按钮点到即清空，不弹确认框。
    - **框选复制 Markdown / LaTeX**：鼠标选中回答后按 `Ctrl+C` 或右键「复制」，只复制选中部分；标题、列表、引用、表格和代码保留 Markdown 格式，公式保留原来的 LaTeX 定界符。选到公式内部时复制完整公式，选到 TikZ 图形时复制对应源码。底部「复制 Markdown」按钮在有选区时复制选中部分，无选区时复制完整回答原文。框选期间暂缓该回答的流式重绘，取消选择后补上新内容；停止后与刷新恢复的历史回答也可复制。成功后显示「已复制」，剪贴板 API 不可用时自动尝试兼容复制。

14. 🧩 对话回答里的 TikZ 自动出图 (Auto-rendered TikZ inside Chat Answers)
    - 模型按 system prompt 输出 ```` ```tikz ```` 围栏（或直接裸写）的 `\begin{tikzpicture}...\end{tikzpicture}`，面板就把它交给本机 TeX Live 编译成矢量图，直接画在回答里；原始代码不再铺在正文中，图下方保留「源码 / 复制」两个按钮随时查看。
    - **先摘出去、再长回来**：Markdown 渲染会做 HTML 转义、`*`/`_` 强调与 `$...$` 公式抽取，这些都会改坏 TikZ 源码（`x_1`、`--`、下划线都是重灾区）。所以整块先换成独占一行的标记，渲染到那一步再原样还给引擎。围栏里的内容不参与这一步（交给围栏分支单独认领），否则 ```` ```latex ```` 里就只剩一个标记了。
    - **只编译闭合的代码块**：必须等 `\end{tikzpicture}` 到手才发起编译——半截代码必然编译失败，而且流式期间每帧都会重试。未闭合时先摆「正在绘制图形…」占位符；若用户中途按「停止」或生成结束时仍未闭合，则退化成可折叠的源码块，而不是留下永远转圈的占位符。
    - **同一段代码只编译一次**：面板是整条消息反复重绘的（流式每帧、图编译完成、刷新恢复历史各一次），因此前后端各有一层按内容哈希的缓存（`render.js` 的 `TIKZ_CACHE` 与 `server.py` 的 `_TIKZ_CACHE`），服务端同时最多跑两个 xelatex 进程。
    - **编译失败不吞回答**：失败时把 xelatex 日志里的报错行回传（例如 `! File ended while scanning use of \tikz@scan@no@calculator.`）显示在图形位置上，正文其余部分照常渲染，源码可展开修改。
    - 导言区一律由 `static/config.js` 的 `LATEX_CONFIG` 接管（tikz / tikz-cd / pgfplots / circuitikz / forest / chemfig / physics + 30 余个常用库）：模型整篇贴过来的 `\documentclass...\end{document}` 会先剥成正文再套上这套头，免得少写一个 `\usepackage` 就整张图编译失败；正文含中文时自动挂 `ctex`（注释里的中文不算）。批注文本框的老路径 `renderTikzToImg()` 行为不变（`extractBody:false`，用户自己写的完整文档原样送引擎）。`server.py` 的 system prompt 里同步写明「用 ```tikz 围栏、只写环境本身、不要写导言区、不要用 `\includegraphics`」。
    - 自检：`node tests/reader-chat-tikz.cjs`（10 项：流式占位不抢跑、单次编译、围栏识别、坏码降级、停止生成、刷新恢复、批注老路径）；真实链路自检：`$env:READER_TEST_REAL_CHAT='1'; node tests/reader-chat-real.cjs`（真的调用 DeepSeek，会消耗额度）。

15. ☁️ 云端批注库：仓库里只有批注，没有 PDF (Cloud Annotation Library)
    - **只同步批注 JSON**，PDF 本身永远留在本机：一份教材的全部批注通常几十 KB，几百本加起来也占不了几 MB。云端路径由 PDF 名字派生——`物理 必修一.pdf` → `annotations/物理 必修一_annotations.json`，与「导出批注」的格式一模一样，所以从仓库里直接下载也能用「导入批注」按钮打开。
    - **按保存即同步**：点保存（或 `Ctrl+S`）时，除了把批注嵌进 PDF 并原位覆盖，还会**顺带把同一份批注覆盖更新到仓库**。上传与写盘并行发起，不增加保存等待；写盘永远是第一优先。
    - **云端失败绝不连累本地**：云端连不上/令牌过期时只把侧栏那枚胶囊变成琥珀色，PDF 照常写盘、照常提示已保存；离线期间攒下的批注存在 IndexedDB 队列里，下次保存、下次打开文档、以及「一键收工」退出前都会自动补传。队列最多保留最近 5 份，真被挤掉时状态提示会如实写明「队列已满，最旧的 N 份未保留」，不会闷声丢掉（本地 PDF 与批注始终不受影响）。
    - **打开文档只提示、不自动改**：本地有记录的最后一次同步时间比云端那份旧时，检索行右端那枚胶囊点亮成蓝色（右上角多一个小圆点，完整句子「云端有更新的批注（时间 · 设备 · 条数）」在悬浮提示里），同时清单顶部的动作条给出「合并 / 忽略」。点「合并」才真正并进来（同样进撤销栈，`Ctrl+Z` 可退）。**任何时候都不会自动覆盖你本地的新批注**——两台电脑同时批注也不会互相吞掉。
    - **状态只占一枚小胶囊**：侧栏「检索批注内容」那一行的右端就是云端入口，同时也是同步状态灯。规则只有一条——**白底 = 眼下没你的事，带底色 = 有事找你**：白底灰图标（空闲）、白底蓝色脉冲（正在同步）、绿底 ☁✓（已同步，6 秒后褪回空闲）、琥珀底 ☁̸（离线待传）、红底 ☁⚠（取回失败）、蓝底 ☁↓（云端有更新）。配色一律跟全站一致（blue 主色 + 绿/琥珀/红只表示结果），不再单独引入第二套强调色。需要你注意时右上角多一个小圆点，完整文字（含「上次同步 20:03」）在悬浮提示里。三样东西并成一行，比原来的「入口行 + 状态条 + 检索行」省下约 50px 垂直空间。**页面一加载就问一次配置**，所以配好了云端的话，一进页面胶囊就在（连份数都是准的），不必先打开一本书才看得到入口；没配好的电脑则整枚隐形，界面与旧版毫无差别。保存下拉里那颗「立即同步」管的只是「当前这份文档的批注」，因此它要等到真正打开一本书之后才出现。
    - **没打开文档也能翻云端书库**：胶囊一进页面就在，所以你可以先逛仓库、搜索、看每本书存了多少条，再决定读哪本。只是「取回」需要一个落点——没开文档时行内的「合并 / 覆盖」会置灰，清单上方明写一行「打开一本书之后才能取回批注」，而不是让你点下去才弹一个框。
    - **取回与本地导入共用一套逻辑**：点那枚胶囊展开云库清单（标题行右侧常显云端已有多少份），每行可「合并」或「覆盖」；**合并 = 取并集**（云端有、本地没有的加进来，本地多出来的原样保留），**覆盖 = 云端那份说了算**（本地多出来的会被删掉，`Ctrl+Z` 可撤回），两者都保留本机的阅读位置与页码偏移。指纹不一致时与「导入批注」走同一个确认框。两个按钮平时隐形、鼠标移到哪一行才在哪一行浮现（和标题栏那颗「复制文件名」同一套做法），所以清单平时只有书名与「设备 · 时间」，一屏能安静地多看几本书。
    - 需要用户点头的动作放在清单顶部的动作条里，只有三种情况出现、平时不占地方：**云端有更新** → 「合并」；**待传 / 上传失败** → 「重试」（先把离线队列补传掉，再补一次当前文档）；**取回失败** → 「重试」重做的是那次**取回**，绝不会变成拿本地批注去覆盖云端那份更新的。右侧的「忽略」任何时候都能点，不存在关不掉的提示。
    - **书多了也能翻**：清单顶部有搜索框（书名 / 云端文件名 / 来源设备 / 当初的本地路径都参与匹配，无匹配时给提示，并显示「匹配 M / 共 N 份」）；排序是「本机最近同步过的在最前 → 其余按拼音」，所以刚批注完的那本永远在第一条。清单接口只返回文件名与体积，时间/设备/条数都藏在文件内容里，因此**按可视行懒取**：由 `IntersectionObserver` 只认「滚到眼前」的行（提前 120px 预取，滚到底不留白），再把同一小段时间冒出来的几条并成一批（每批最多 8 条，服务端并发取）。于是打开面板的代价与你**实际看了几行**成正比，而不是与你**存了多少份**成正比——60 份的实测：打开只发 2 次请求（补 15 行），滚到底累计 4 次（30 行），而不是把 60 份全读一遍。面板默认吃服务端 20 秒缓存，反复开关不再打接口，↻ 才强制刷新，并顺带重读一次 `cloud_config.json`——改完配置不必刷新整个页面。标题行只写「云端批注库 + 份数」，provider / 目录 / 本机名属于排障信息，挂在悬浮提示里。
    - **清单再长也不会顶出侧栏**：面板高度按侧栏剩余空间实算（头部 + 动作条 + 搜索框的实际高度都算进去），清单超长就在面板内部滚动，窗口拉矮、旋转屏幕、动作条出现消失都会重算。写死视口百分比（`52vh`）在矮窗口下会让面板撑出侧栏、被 `overflow-hidden` 从底下裁掉，最后一行看不全也够不着——这条是实测抓出来的。
    - **令牌只存在于 `server.py`**：浏览器只跟 `127.0.0.1:8080` 说话，既拿不到令牌，也绕开了浏览器直连 `api.github.com` 必然撞上的 CORS 限制。
    - **同名不同文档不会互相覆盖**：上传前先比对云端那份的指纹，不是同一份文档就自动改存 `物理 必修一__3f2a91c0_annotations.json`，两边都保住。
    - ⚠️ **真实 GitHub / Gitee 的目录接口只给文件名与体积，不返回文件内容**（内容只有单独取某个文件时才有）。时间、设备、条数、指纹这些元信息都在文件内容里，所以状态查询会按需补 1~3 次单文件请求，云库清单则只补「滚到眼前的那几行」（`IntersectionObserver`，每批最多 8 条，服务端并发取）。这一条是被真机验证抓出来的：早期版本依赖「目录里就能读到内容」，导致「打开文档时提示云端更新」在真实仓库上永远不触发；现在两个自检脚本的假服务器都照着真实的抠门行为来，这类偏差不会再溜过去。
    - 超过 1MB 的批注（几千条标注的教材）在 GitHub 上自动改走 Git Data API（blob → tree → commit → 移动分支引用），不会卡在 Contents 接口的文件上限上。
    - 配置（二选一，改完即生效、不必重启）：
      - 直接改 `server.py` 顶部的 `CLOUD_SYNC`：填 `provider`（`github` / `gitee`）、`owner`、`repo`、`token`，再把 `enabled` 改成 `True`；
      - 或在 `server.py` 同目录放一个 `cloud_config.json`，只写要覆盖的几项（全部可配项与中文说明都在 `server.py` 顶部的 `CLOUD_SYNC` 注释块里，照着一项项写即可；本仓库不再附示例文件，避免有人误把示例当配置）。
    - 令牌怎么拿：**GitHub** → Settings → Developer settings → Personal access tokens (Fine-grained)，仓库权限只要 `Contents: Read and write`；**Gitee** → 设置 → 私人令牌，勾选 `projects`。仓库新建一个空的私有仓库即可，目录（默认 `annotations`）会在第一次保存时自动建出来。
    - 排障：`cloud_config.json` 里的 `proxy` 默认 `system`（跟随系统代理，GitHub 在国内通常需要）；若本机代理是坏的 Clash 残留，改成 `""` 即强制直连，或填 `"http://127.0.0.1:7890"`。`mirror_paths: true` 会再按 PDF 所在的上一级文件夹归档，适合不同文件夹里放同名教材的情况。配置是否有效由 `POST /api/cloud-anno {"action":"test"}` 一次性验证（仓库是否可达、分支、目录、已存几份批注）。
    - 自检：`python tests/test_cloud_backend.py`（48 项，用本机假 GitHub / 假 Gitee 验证命名规则、新建/覆盖、sha、大文件通道、Gitee 差异、错误提示，并走一遍真实 HTTP 路由，不联网、不需要真账号）；`node tests/reader-cloud-sync.cjs`（15 项端到端：入口一进页面就在且没开文档时取回置灰、保存即上传、覆盖同一文件、断云不影响本地写盘、离线补传、打开只提示不自动改、合并可撤销、云库清单懒取详情与搜索、取回不丢本机阅读设置、`enabled=false` 时完全隐形）。

| :--- | :--- | :--- | :--- |
| **旧页面与新脚本混用** | 偶发打开 PDF 失败，提示 `Cannot access 'searchSidebarView' before initialization`；主窗口 Ctrl+F5 后，新标签页仍可能出错 | 不同 `?open=` 地址可持有各自的旧 HTML，却共用新版脚本。HTML 发送 `no-store`；JS/CSS 和两个 Worker 各自按 SHA-256 内容指纹生成地址，未变化的资源可长期复用；无指纹的静态资源按内容 ETag 校验，避免旧时间戳误返回 304。迁移到新缓存规则时清理一次旧 HTTP 缓存，保留批注存储；启动器和两种新窗口入口继续生成新地址。可选按钮绑定仍保留兼容保护 | `python tests/test_static_assets.py`、`node tests/reader-resource-updates.cjs`、`node tests/reader-startup.cjs` |

| **批注层残留缩放矩阵** | 加自由直线 / 自由高亮块时，刚按住拖动的那一截条带不在鼠标下方，而是**偏移一段距离才开始画线**；松手后批注又跳回正确位置 | 缩放手势期间批注层靠一个临时 `transform: scale()` 跟着页面走（`scaleAnnotationLayer`），而手势结束后 wrapper 尺寸还会被 `drawPdfPage` / `layoutPdfWindow` 改写。旧代码在**手势之外**也照挂这个矩阵，于是页面回挂（缓存页带旧 layer 一起回来）时会留下「矩阵是 150%、wrapper 已是 100%」的组合：层的坐标系和 wrapper client rect 差一个系数，拖拽预览画进被缩放的坐标系里就偏了；松手落库重建视图顺手清掉矩阵，图形又跳回原位。修复：`scaleAnnotationLayer` 只在 `state.isZooming` 期间挂矩阵；`renderAnnotations` 发现陈旧矩阵（`_pdZooming`）时按当前尺寸重建；绘图等手势开始前先经 `ensureAnnotationLayer()` 对齐坐标轴 | `node tests/reader-draw-axis.cjs` |

> 编码看门狗如实返回 PASS/FAIL；控制台隐藏脚本在能力不足时（控制台本身就不可见，构不成「可见 → 隐藏」对照）会报 `SKIP`，不会给虚假的 PASS。

缓存机制需要同步 `app/server.py`、`start.bat` 和 `static/js/foundation.js`、`static/js/annotation-loader.js`、`static/js/document.js`、`static/js/outline-search.js`，然后重新通过启动器启动服务一次。启动器会自动避开升级前的旧入口缓存。之后修改 HTML、JS、CSS，普通刷新或新开 PDF 标签页即可加载新文件，无需手动清缓存、Ctrl+F5 或维护版本号；修改 Python 服务代码时仍需重启服务。资源地址仅随内容变化，未改动的脚本、样式和 Worker 可以复用；字体等未带指纹的资源用 ETag 校验后返回 304。浏览器用 `readerCachePolicy` Cookie 记录迁移状态，旧 HTTP 缓存只在迁移时清理一次，不清除 localStorage、IndexedDB 中的设置和批注，也不改变本机 PDF 文件。

手机手写/白板配对后保留会话，因此 `/api/formula/phone` 的 `state` 请求属于状态同步，不调用识别模型。面板可见时约每 700 毫秒同步，面板收起或页面在后台时改为约每 30 秒保活；重新展开、打开或回到页面立即取回最新状态，不需要重新扫码。请求失败会逐步延长重试间隔。成功的状态查询不打印访问日志，配对、识别、清空、关闭和失败请求仍保留日志。
